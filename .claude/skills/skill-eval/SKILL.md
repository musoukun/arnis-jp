# スキルのテストを、記録から振り返る

スキルを1回テストしたら、このスキルで記録を残す。記録を見て、スキルのどこを直すかを決める。

## 何が分かるか

記録の HTML の一番上は、次の表になる。

| 取れる情報 | 分かること | スキルの直し方 |
|---|---|---|
| どの手順に時間がかかったか | 遅い手順がどこか | その手順のやり方を、スキルで短くできないか見直す |
| 前の手順に戻った所（やり直し） | 一発で進めなかった所 | 戻った原因（足りなかった情報や決まり）を、戻る前の手順に書き足す |
| 人が「それ違う」と言った所 | 一発でできなかった所 | 言われた中身を、スキルの決まりにする |
| 正解との一致（%） | 出来上がりの差 | 違う所の原因になったスキルの記述を直す |

その下に「スキルの流れと時間」の図（箱＝スキルの手順、色が濃いほど時間が長い、赤の破線＝前の手順に戻った）。
同じ図を draw.io で開いて直せる `.drawio` も一緒にできる。
細かい部分（時間の順の流れ、何の作業が遅いか、正解との絵の比べ方、前の回との比較）はたたんである。

## 使い方

1. テストは、新しいセッションをプロジェクトの一番上で開いて行う（別のフォルダで開くと、記録が見つからない）
2. テストが終わったら、最近のセッションを番号つきで出して、テストのセッションの番号を確かめる
3. その番号で記録を残す

```text
python .claude\skills\skill-eval\scripts\skill_eval.py <プロファイル> list
python .claude\skills\skill-eval\scripts\skill_eval.py <プロファイル> report <番号> [--code 設計名] [--compare 設計名] [--images "正解=絵1.png,テスト=絵2.png"]
```

- `<プロファイル>` は `profiles/<名前>.json`（評価するスキルごとの設定）。今あるのは `image2mc-builder`
- 記録は作業フォルダ `skill_eval/reports/`（プロジェクトの一番上。git の対象外）に、`.md`・`.html`・`.drawio` でできる。
  テストを重ねると `history.csv` に1行ずつ足され、「前の回と比べる」で並べられる
- 番号は新しいセッションができるとずれるので、`list` の直後に使う。日本語が化けるときは、先に PowerShell で `$env:PYTHONIOENCODING="utf-8"`
- テンプレートや設定を直したあとは、作った記録を描き直せる: `python …\skill_eval.py rerender <記録の HTML> --recount`

## 別のスキルに使う

`profiles/image2mc-builder.json` をコピーして `profiles/<スキル名>.json` を作り、スキルに合わせて書き換える。
大事なのは `flow`（スキルの手順と、その手順に当たる作業の目印）と `purposes`（作業を「何のために」の言葉にする表）。
書き方と、各項目の読み方は [references/guide.md](references/guide.md)。

## 限界

- 今は Claude Code の記録だけに対応（ほかの AI の道具は、記録の置き場所と形が違う）
- 時間は記録の時刻から計算する。「考えている時間」の中で、頭の中で考えた時間と文を書いた時間は分けられない
- 正解との比較は、スキルごとに比べる命令を用意する。正解を取ったあとで条件（ワールドや建物の倍率）が変わると比べられないので、そのときは絵で見比べる
