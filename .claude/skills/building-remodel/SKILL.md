# 写真1枚から Minecraft の建物を作る

- **入力**: 写真1枚（ストリートビューのスクショ等）＋ arnis が保存した OSM データ。他の画像生成 AI は使わない
- **ゴール**: 写真の建物が「だいたい近い」見た目で建つこと。細部の完全一致は狙わない
- **正解例**: ガスト 堺北花田（ユーザー評価「かなりクオリティが高くて感動した」。仕様は下の「6. 正解例」）
- **サンプル**: KFC 堺北花田。設計 `tools/remodel/designs/kfc_kitahanada_v2.py`（1ファイルで書いた完成例）、お手本と部位の拡大 `examples/kfc_kitahanada/`。
  新しい建物は、パーツに分けたフォルダの型 `designs/_parts_template/` から作る（Step 3）

- **分からない所は、決めつけずに聞く**（下の「0. 聞いてから作る」）

---

## 0. 聞いてから作る（最優先の決まり）

写真やお手本から**読み取れない・確信が持てない所は、推測で埋めずにユーザーに聞く**。
推測で建てると、壊して建て直す手間がかかり、同じ質問を後で何度もすることになる。

| いつ聞くか | 例 |
|---|---|
| 写真に写っていない・隠れている | 人や看板の陰、裏の面、屋上の奥 |
| 2通り以上に読める | 「段は飾りか通路か」「看板はどの面を向くか」「扉はどこか」 |
| 部位表の欄が埋まらない | 大きさ・位置・向き・形（フル／ハーフ／塀／柵）のどれかが決められない |
| お手本と写真が食い違う | お手本の作りと実物の写真で、位置や数が違う |
| 道具で作れない形が要る | 部品の不足（作り方を変えてよいか、道具を足すか） |

**聞くとよいこと**: 位置と幅（扉・窓の幅・看板の位置・通路）、建物の大きさ（正面の前に何マス空けるか・左右に何マス広げるか）、**地面に立つ物（立て看板・のぼり・ポール）の根元がどのマスに刺さっているか**（写真で決められない時。[辞書](recipes.md)の「立て看板」）。
**聞かないこと**（自分で決め、施工前のプレビューで見せて直してもらう）:
- 辞書（recipes.md）に作り方と数が書いてある部位（屋上の柵・塔・帯など）。聞く前に辞書を引く
- ブロックの形（柵に見える物は柵、薄い物はハーフ）

聞き方:
- **フォームは型から作り、出すのは Sonnet のサブエージェントに任せる**（重いモデルが HTML を書き出すと遅い。ユーザー指定 2026-10-04）:
  0. **質問を作る前に面の長さを測る**: 型のフォルダ `designs/_parts_template/` を `designs/<建物名>/` にコピーし、`base.py` の `WAY`・`EXCLUDE`・`SHAPE`（ずらす・広げるの推測）を入れて
     `python run.py <建物名> faces`。スライダーの `length` は面全体のマス数、位置は出てきた k（左の角が 0）で書く。
     建物の大きさを聞く質問の答えで SHAPE が変わったら、測り直す
  1. 質問の一覧を JSON に書く（書き方は `tools/remodel/ask_form.py` の先頭）。種類は3つ:
     位置・幅 = `slider`（**スライダーで動かすと、ブロックで描いた正面の壁の上で扉や看板が動く**）／
     作りの案 = `choice`（**上から見た図をブロックで描いて**並べる。何を比べているのかが図で分かるように）／
     ブロック = `block`（**色ではなく実物のテクスチャの見本**）
  2. `python tools/remodel/ask_form.py <質問.json>` で `out/ask_<名前>.html` を作る
  3. Agent（`model: "sonnet"`）に頼む: 「`out/ask_<名前>.html` を Read で読み、ToolSearch で
     `select:mcp__visualize__read_me,mcp__visualize__show_widget` を読み込み、`read_me`（modules ["interactive"]）を呼んでから、
     `show_widget` の widget_code にファイルの中身を一字一句そのまま渡す。報告は呼べたかだけ」
  4. 答えは「〇〇 の答え: 扉の位置=北の角から11マス / …」の1行でユーザーから届く。フォームを撮って確かめる必要はない
- **別々の部位は、別々の質問にする**（左右の通路なら「左の通路の位置」「右の通路の位置」の2問。1つの操作で2つを動かさない）
- **ゲームの座標（x・z の数字）を質問に出さない。** 相手に分かるのは「北の角から何マス」「正面の真ん中から南へ何マス」「左右」「手前・奥」
- 絵には目の位置と向き、北と南（左右）、正面の真ん中の目印、人の目印（高さ2マス）を入れる
- 短い確認だけなら、自分の理解を AA（平面か立面の文字の図）で描いて見せ、「ここで合っていますか」と聞いてよい（描き方は 1.5 の「AA で質問」）。
  上から見た図と正面から見た図を1つの絵に混ぜない
- 1回にまとめて聞く（分からない所を全部書き出してから。1つずつ小出しにしない）
- 選択肢があるなら並べて、おすすめを1つ示す（`AskUserQuestion` を使える時は使う）
- **答えをもらうまで、その部位は作らない**（ほかの決まっている部位は進めてよい）
- 答えは部位表と設計ファイルの説明に書き残す（次に同じことを聞かない）

## 1. 変換の法則（このスキルの本体）

正解例と、上手な Minecraft の再現作品（高層マンション・百貨店）の分析から導いた。

### 法則1: 大きさ — 目で見た比率と、人の体で決める（画素を測って換算しない）
**1.4 はワールドの縮尺で、ユーザーの「黄金比」**。ユーザーが自分の目で見た世界とゲームの中の自分の体との比率から決めた数で、
`arnis --scale 1.4` でワールドを生成した時点で、道路・敷地・建物の平面・高架にもう入っている。
**部位（看板・塔・柵・文字・植え込み…）に 1.4 を機械的に掛けない。** 掛けると二重に大きくなる。

| 決めること | 決め方 |
|---|---|
| 平面（幅・奥行き・形） | **建物の幅と奥行きは 1.3 で作る**（ワールドは 1.4 のまま、建物だけ OSM の形を真ん中から 1.3/1.4 に縮める。`parts.building_cells`。ユーザー「実際に見て 0.1 引いたくらいがちょうどよい」）。そのうえで `parts.grow_footprint` で整える（設計の `SHAPE`）。正面の前（壁から歩道の手前まで）に**6マスの余裕**（通り道・衝立・植え込み）が無ければ建物をずらす。正面の幅も**比率に合わせて数マス広げてよい**。1マスの段や傾きはそろえる。ずらす量・広げる量は**質問で聞く**（KFC は東へ2、北へ2・南へ1、北面をそろえた） |
| 1階の高さ（地面〜帯） | 店舗はおよそ **5 マス**（正解例ガストの柱5）。ここを建物全体の基準にする |
| それ以外の部位の大きさ | **写真を目で見て、基準との比率で決める**（「塔は1階より少し低い」「看板は入口と同じくらいの幅」「屋上の柵は1階の半分くらい」） |
| 人との比べ | プレイヤーは高さ **1.8 マス**。看板・文字・塔・柵を、**その前に人が立った時に大きすぎないか**で確かめる（実物の看板は人の背丈かそれより少し大きい程度） |
| 細いもの | どんなに細くても最低1マス（薄い物はハーフや柵・板で） |

**やらないこと**: 写真にマス目を引いて画素を数える／画素を m に直す／m に 1.4 を掛ける／「低めに出るから大きく」と上乗せする。
人が一目で分かる比率を、そのまま目で見て決める。マス目は、比率がどうしても決められない時だけ使う。

### 法則2: 大きいものから合わせる（大きさで扱いを変える）
| 実物の大きさ | 例 | 扱い |
|---|---|---|
| 5m 以上 | 輪郭、段差、塔と基壇 | 比率を正確に（OSM＋高さの法則） |
| 1.5〜5m | 階、柱間、ひさし、帯 | **数**を合わせる（何段、何マスおき） |
| 0.5〜1.5m | 窓の格子、ルーバー、細い窓 | **密度と凹凸**を合わせる（数はおおよそ） |
| 0.5m 未満 | 手すり、目地、窓枠の細部 | 捨てるか、帯・面に吸収 |
| 文字・ロゴ | 店名、看板 | 法則6 |

### 法則3: 壁は「段の積み重ね」で書く
写真の壁を、下から何の段が何段あるかに分解する（`STACK`）。段の種類は `parts.py` の
`glass`（窓。柱つき・奥に引っ込める）/ `solid`（無地）/ `frame`（上枠）/ `frame+awning`（上枠＋ひさし）/
`frame+balcony`（上枠＋張り出し）/ `band`（帯）。
| 建物の型 | STACK の目安 | 根拠 |
|---|---|---|
| 平屋の店舗（ファミレス等） | `glass×3, frame+awning, band`（柱5マス） | 正解例 |
| 平屋の店舗・ひさし無し（コンビニ等） | `glass×3, frame, band` | 正解例から類推 |
| 住宅・マンションの1階分（4マス） | `glass×3, frame+balcony` を階数だけ繰り返す | 作例分析（**要検証**） |
| オフィス・商業の1階分（5マス） | `glass×4, frame` を階数だけ | 作例分析（**要検証**） |
階数は写真で数えて**数を合わせる**（法則2）。1階分のマス数は丸めてよい。

### 法則4: 屋根
| 写真の屋根 | ROOF | 作り方 |
|---|---|---|
| 寄棟（四方に傾く） | `{"type": "hip", "rise": r}` | 軒先は壁の1マス外。ハーフで 1:2 に上がる |
| 切妻（二方向） | `{"type": "gable", "rise": r, "ridge": "x"または"z"}` | 棟の向きを写真で決める |
| 陸屋根（平ら） | `{"type": "flat"}` | 1マスの手すり壁 |
`r` は基本 2.5（頂部 = 柱 + 3）。写真で明らかに急な屋根なら増やす（0.5 刻み）。屋根は暗い色の方が引き締まる。

**屋上の柵・ルーバー**（陸屋根の店に多い）は [部位の辞書](recipes.md) の「屋上の柵」に従う（KFC は `nether_brick_fence` を3段、向こうが透ける）。
- 段数は、写真を目で見て1階の高さとの比で決める（屋上の物は低い。帯の上に5段も積まない）
- 帯の陰で下の段が隠れないか、横からの絵で確かめる

### 法則5: 奥行きで影を作る（最低3つの面）
張り出し（ひさし・ベランダ・軒 = +1）／壁の面（0）／引っ込み（窓のガラス = −1）。
平らな壁に色を塗るだけだと模型に見える。窓は `glass` の段が自動で1マス引っ込める。

### 法則6: 色は「素材の種類」で選び、差し色は全部残す
**まず [部位ごとの作り方の辞書](recipes.md) を読む。** 色と種類だけで決めると全部フルブロックの塊になる。
部位ごとに、ブロックの形（フル／ハーフ上下／階段／柵／板ガラス）・厚さ・重ね方・置き方を辞書から決める
（植え込みの縁はハーフを積む、軒の下に軒天と吊りランタン、屋上の格子は透ける柵＋支柱、看板の枠と立体文字は1マス飛び出す…）。
| 現実の素材 | ブロック（`parts.DEFAULT_PAL`） |
|---|---|
| コンクリート（舗装・柱・電柱） | `stone_bricks` / 柱は `stone_brick_wall` |
| 黄色い点字ブロック | 木の板（`bamboo_planks`） |
| 店先の赤茶のタイル | `polished_granite` |
| レンガ | `bricks` |
| 生け垣 | `oak_leaves[persistent=true]` |
| 布のひさし | 色付きウールの縞（例 `red_wool`/`white_wool`） |
| ガラス窓 | `gray_stained_glass` |
| 窓枠・暗い柱 | `polished_blackstone` |
| 白い外壁・パネル | `smooth_quartz` / `white_concrete` |
| ブランドの色 | その色のコンクリート（`red_concrete` 等） |
| 瓦・暗い屋根 | `deepslate_tile_slab` |
| 金属のラック・柵 | `iron_bars` |
| 黒いレンガ調の外壁・塔 | `polished_blackstone_bricks` / `deepslate_bricks` |
| 木の枠・木のルーバー | `spruce_planks` / `spruce_trapdoor` |
- **色は対応表で選ぶ**（`block_catalog.py`）。全ブロック（1.21.11 の 1162 個）の「テクスチャ・平均色・一番多く使われている色の範囲とその割合」の表。
  一覧は `python block_catalog.py build` で `out/block_catalog.html`（色相順、名前で絞り込み）
- 手順: ① 写真の範囲を決める → ② **素材の種類を意味で決める**（レンガ・コンクリート・木…）→
  ③ `python block_catalog.py match <写真> x0 y0 x1 y1 6 <種類>`（例 `bricks`）で、その種類の中で色の近い順に
  **実物のテクスチャと写真を並べた絵**（`out/match_*.png`）を作る → ④ 絵を見て模様も近いものを選ぶ
- 種類で絞らないと、色だけ近い別物が上に来る
- 写真は曇りや日陰で色が暗く・くすんで写る。
  差し色・ブランドの色は表の答えより**鮮やかな方**（`red_concrete` 等）を選ぶ
- 差し色（帯・ひさし・看板・旗）は**位置と大きさごと全部**残す。白い建物ほど差し色がその建物らしさを決める
- 帯が実物より太くなる（0.4m → 1マス）ので、赤が多く見えたら帯を壁の線（軒の影の中）だけにして、屋根の量で比率を戻す

### 法則7: 文字・ロゴは地図アートで実物大
- **地図アートにする物**（額縁に入れた地図。1マスに 128×128 ドット）: ロゴ・店名の文字・壁の看板・立て看板（案内・矢印）・ポスター。
  **ブロックの塊で代わりにしない**。**写真から中身（文字・色・形・配置）を読み取り、`tools/remodel/sign_art.py` の型で描く**
  （[parts.md](parts.md) の「看板の絵」）。写真の切り抜きは、斜め・小さい・反射でぼやけるので、描けない時の最後の手段
- 看板の裏には**色の近いブロック**（`SIGN_BACKING`）を置く。額縁が見えなくても看板の色の塊に見える
- ブロックの塊でよいのは、写真で絵も文字も読めないほど小さい物（機械・ボックス・細かい案内板）だけ
- 額縁の下や横に支えが無いと浮いて見える。根元まで埋める

### 法則8: 周りまで作る（写っているものだけ）
| 写真の物 | 部品（`parts.py`） | 大きさ |
|---|---|---|
| レンガの植え込み＋生け垣 | `planter` | 縁1マス、生け垣は2段まで |
| 街路樹・小さな木 | `small_tree` | 3マス。窓の前には植えない |
| のぼり旗 | `nobori` | 柵の柱＋模様付きの旗（約3マス） |
| 駐輪ラック | `bike_racks` | 1マス |
| 電柱・看板の柱 | `pole` | 電柱 12マス |
| 店先のタイル・点字ブロック | `ground` | 地面の張り替え |
**窓とひさしを隠さない**: 生け垣は2段まで、木の葉は窓の無い所に。

### 法則9: 入口は必ず「入れる」ようにする
プレイヤーは高さ 1.8、ジャンプで上がれるのは約 1.25。見た目より先に通れることを守る。
| 入口の型 | 作り方 |
|---|---|
| 段差なし（店舗の基本） | 外の地面と室内の床を同じ高さに。開口は高さ3（住宅は2）×幅2以上 |
| ハーフの段（0.5） | 入口前にハーフブロック、室内の床もハーフで同じ高さに（ジャンプ不要） |
| 1段上がる（レンガの土台の上に建つ店など） | 設計に `PLINTH = 1`。土台がレンガになり床が1段上がる。外はハーフずつ上がる（`entrance(..., steps="slab")`。階段ブロックにしない） |
| 扉の前だけフルブロック（よく使う作り） | 扉の前の1マスだけフルブロック、その手前はハーフ。`entrance(..., steps="landing")`。[辞書](recipes.md)の「扉の前の踏み台」 |
- `parts.entrance(c, 壁のセル, 外の向き, height=3)` を `extras` の**最後**に呼ぶ（壁・窓・植え込み・像などを上書きして通り道を空ける）
- 入口の前後2マスに、像・看板・ラック・植え込みを置かない
- 写真で入口に階段があり、建物の足元にレンガ・石の帯が見えたら**土台（`PLINTH = 1`）**。床・壁・窓はすべて土台の上から始まる

**入口のデザイン**（正解例の分析から。入口は「ひと目で入口と分かる」ことが大事）:
- 入口は**柱に挟まれた凹み**。両脇に壁の線で2マスずつの柱（帯の下まで）、その1マス奥にガラスの扉
- 扉は床から3マスのガラスに見せる（動く2段 ＋ 上の明かり取り）。奥の室内の明かりが見える
- 入口の段と床は、[辞書](recipes.md)の「入口のまわり」「扉の前の踏み台」に従う（ハーフずつ上がり、扉の前だけフルブロック）
- **入口の前と左右3マスに看板・柱を立てない**（案内看板は窓の前へ）
- 確認は**入口の正面から描いた絵**で（写真の斜めの視点だけでは入口の違いに気づかない）

**自動扉を基本で付ける**（店舗はガラスの自動扉）: `entrance` の直後に
`used = parts.auto_door(c, 入口の壁セル2つ, 外の向き)` を呼ぶ。
- 柱に挟まれた凹みの奥に、ガラスの扉（幅2・高さ2＋明かり取り）。外と室内の感圧板で開き、離れると閉まる
- **回路は完全に隠す**: ピストン・粉・トーチは石レンガ（`door_frame`）で天井まで包み、トーチは床の中、配線は床下（[辞書](recipes.md)の「自動扉の仕掛け」）
- 仕組み: 粘着ピストン4本が左右からガラスを押し出して閉じている（床の中のレッドストーントーチで常時通電）。
  感圧板 → 床下の粉 → トーチの台に通電 → トーチが消える → ピストンが縮んでガラスを壁に引き込む
- 配線は床下（床 − 1）に通すので **`PLINTH = 1` 以上が必要**（0 だと扉を付けずに開口のままになる）
- 入口の壁セルは**ちょうど2つ**。左右に4マスずつ仕掛けの幅が要る（壁の端・塔に掛からない位置を選ぶ。両脇2マスは柱になる）
- ピストンは置いた瞬間の通電で伸びるので、`build` の最後に順番どおり置く（`Blocks.ordered`、`run.py` が自動でやる）
- 施工後に `python run.py <建物> doortest` で試す（感圧板ごとに防具立てを置いて、開く・閉じるを確かめる。誰かがログインしている時だけ動く）

### 法則10: 正面から見える室内を作る（窓の奥が空っぽだと模型に見える）
`parts.furnish(c, 窓の面, avoid=used)`（`used` は `auto_door` の戻り値）。
| 物 | ブロック | 置き方 |
|---|---|---|
| 机 | 柵1本（`spruce_fence`）＋ 感圧板 | 窓の面の壁から 3 マス内側、4 マスおき |
| 椅子 | 階段（`spruce_stairs`） | 机の前後（壁から 2・4 マス）。背もたれは机の反対側 |
| 明かり | 鎖（`iron_chain`）で吊ったランタン | 天井から、窓の高さ（床 + 3）まで下げて外から光が見えるように |

## 1.5 ミスを防ぐ決まり（必ず守る）

どれも、お手本を目で見る前に別の物で決めて失敗したことから作った決まり（経緯は `tools/skill_eval/profiles/building-remodel.md` の「スキルから移した失敗の経緯」）。
- 部品で作れない形は、形を変えずに**道具の側を直す**（部品の不足として先に報告）
- **画素を測らない。目で見た比率と人の体で決める**（法則1）。1.4 はワールドの縮尺（ユーザーの黄金比）で、部位に掛けない
- 部位ごとの数（幅・高さ・奥行き・段数・位置・向き）は**お手本を見て部位表に書く**。**古い設計の座標を使い回さない**
- 指摘を受けたら、その原則で**全部の部位を点検し直す**
- 部位を見る前に、**歩道から扉まで人がどう歩くか**（車ならドライブスルーの通路）を平面の AA に描く。**段・階段・植え込みの切れ目は通路の印**。「なぜここに段があるのか」を必ず考える
- 入口・通路は、**横から見た高さの図（断面の AA）を描く**。歩道→通路→通り道→扉の各マスの床の高さをハーフ単位で書き、段をどこに置くかを決めてから作る
- 衝立・看板・ひさしなど**前に出る物を足したら、上から見た図で軒の線と重ねる**。入口のまわりは軒を前に出して覆う（覆わない時は理由を書く）
- 部位表で**ブロックか飾りか**を分ける。ランタン・トーチ・鎖・感圧板・旗などの飾りは、**ブロックを全部置いた後に最後に取り付け**（`Blocks.decor`、`run.py` が自動）、**付いたかを1つずつワールドで確かめる**
- 高さは**名前の付いた基準（地面 G・床 F・帯 top）から**書く。**接する部位は相手の基準で書く**（衝立の上 ＝ `top - 1`、ポスターは植え込みの段 `G + 1` の上から）。施工の前に `run.py section` の断面と `run.py check` を必ず見る
- 施工前に **お手本と同じ視点の絵** と、**部位ごとの横・正面の近い絵**を作り、部位表の数と1つずつ照らす。**入口の前に人（高さ2マスの目印）を置いて**、看板・塔・柵が人に比べて大きすぎないか見る

**部位表**（設計を書く前に必ず作る。1行1部位）:
```
部位 | ブロックか飾りか | ブロック | 形（フル/ハーフ上下/塀/柵/板） | 幅×高さ×奥行（お手本を見て決めたマス数） | 1階の高さ・人との比べ | 位置（入口の中心・角からのずれ） | 高さの基準（何の上に載り、何の下に接するか） | 向き | 根拠（拡大画像のパス）
例: 屋上の柵 | ブロック | nether_brick_fence | 柵 | 縁に沿って×3段×1 | 1階の半分ちょっと・人の背丈くらい | 北と西の縁、塔の所は切る | 屋根（top）の上に載る | — | examples/kfc_kitahanada/parts/louver.png
例: 帯 | ブロック | 赤のハーフ | ハーフ | 全周×0.5×張り出し1 | 薄い線 | 1階の上端 | 壁の上（top） | — | examples/kfc_kitahanada/parts/band.png
例: 衝立 | ブロック | 深層岩レンガの塀＋ポスター | 塀 | 4×5×1 | 1階と同じ高さ | 扉の前、通り道の外 | 植え込みの段（G+1）の上に載り、上は帯（top）の真下に接する | 西 | examples/kfc_kitahanada/parts/entrance.png
```
報告では、建てた物の数と部位表の数を並べた表を出す（合っていない所は「合っていない」と書く）。

**分からない所は、AA（文字の図）で質問してから作る。** 文章だけの質問は、写真の読み違いをそのまま問うことになり、
相手に意味が通じない。
- 平面（上から見た図）か立面（正面から見た図）を AA で描き、自分の理解を見せてから「ここで合っていますか」と聞く
- 目の位置と向き（👁 と ↓）、前後の順番（手前→奥）、マスの幅（░ 1つ = 1マス）を図に入れる
- 例（KFC の入口。正面から見て、手前から奥へ）:
```
   👁
   ↓
 塀 ポスター 塀      ← 深層岩レンガの塀で囲ったポスター（衝立）
     通路           ← 人1人分（1マス）
      扉            ← 正面の中央
```
```
 横から見た高さ（断面。左が歩道、右が建物。░ = ハーフ、█ = フルブロック）:
```
 歩道    通路の入口   通り道      扉の床
 ____    ░           ░░░░░       █        ← 歩道より ハーフ → 通り道もハーフ → 扉で1段
```
```
 歩道
 ───────────────────────────────────────
  植え込み（塀の縁＋間に砂利）  ↓通路  植え込み
 ═══════════════════════════  ░  ════════════
  ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░   ← 人1人分（1マス）の通り道
 ─建物の壁─────────────────[扉]───────────
```

## 2. 作り方（手順）

準備（ワールドの縮尺・サーバーの起動・視野角）は [reference.md](reference.md) の「準備」。

### Step 1: 建物と敷地を決める（ローカルデータだけ）
1. arnis の OSM JSON（`%LOCALAPPDATA%/arnis/osm_cache/` や `doc/kitahanada/osm_data.json`）で、
   店名の POI（`amenity`/`brand`/`name`）を探し、それを含む `building=*` の way ID を取る。
   日本語が文字化けするので Python で、`PYTHONIOENCODING=utf-8` を付けて実行する:
   ```python
   from parcel import OsmGeometry, ROOT, cells_in
   geo = OsmGeometry(ROOT / "doc/kitahanada/osm_data.json")
   for n in geo.nodes.values():                      # 店の POI を探す
       t = n.get("tags") or {}
       if "KFC" in str(t) or "ケンタッキー" in str(t):
           x, z = geo.to_mc(n["lat"], n["lon"]); print(n["id"], round(x), round(z), t.get("name"))
   for wid, w in geo.ways.items():                   # その点を含む建物
       if "building" in (w.get("tags") or {}) and (round(x), round(z)) in cells_in(geo.polygon(wid)):
           print("WAY =", wid, w["tags"])
   ```
2. 敷地 = その建物を含む `landuse` ∪ 建物のまわり5マス。**歩道・道路の手前で切る**。隣の構造物は `EXCLUDE` に
3. Web で敷地を探さない。ワールドを作り直すと座標が変わるので、毎回 OSM から変換する（コードが自動でやる）

### Step 2: 写真を読む（モデルの仕事。この表を埋めてからコードに入る）
**写真をそのまま目で見て決める。マス目を引いて画素を数えたり、m に換算したりしない**（法則1）。
**拡大の切り抜きは、次の時だけ作る**（位置・幅・数は質問と辞書で決めるので、拡大はいらない）:
ブロックを選ぶ時（模様や色をテクスチャと比べる）／柵か板か・ハーフかフルかが全体の絵では本当に判断できない時。
看板の中身（文字・色・形）を読むだけなら拡大しない（読んで描く）。

```
■ 1階の高さ: 店舗はおよそ 5 マス（これを基準にする）
■ 型（法則3の表から）: ______ → STACK = [...]
■ 屋根（法則4）: hip / gable(棟の向き __) / flat
■ 部位表（法則1.5）: 部位ごとに、形・ブロック・大きさ（1階の高さとの比、人との比べ）・位置・向き
   例: 塔 = 1階より少し低い・幅は入口2つ分くらい・入口の真上／看板 = 人の背丈より少し大きいくらいの正方形
■ 窓のある面: __（写っていない面は入れない）、柱の間隔 ___マス
■ 差し色の区画: ______（位置と大きさ）
■ 看板: 名前 / 大きさ（人と比べて）/ 色 / 位置と向き（店の顔なら地図アート）
   立て看板は、根元のマス（どこに刺さっているか）と足（細ければ木の柵1本、太ければ塀1本）も書く
■ 入口: どの面、凹み（ポーチ）か、段があるか（あれば PLINTH = 1）、柱・床の色
■ 外まわり（写っている物だけ）: ______
```

**Step 2 の最後に「分からない所の一覧」を作る。** 1つでもあれば、AA を付けてユーザーに聞き、答えをもらってから Step 3 に進む（0. 聞いてから作る）。

### Step 3: パーツに分けて、Sonnet の Agent に並列で書かせる
建物を部位ごとのファイル（パーツ）に分け、ゴールが決まっている部位は Sonnet の Agent に1つずつ並列に書かせる。
最後に組み立て役（`__init__.py`）が全部を集めて1つの建物にする。1人で全部を順に書くより速い。
型と中身の説明は [parts.md](parts.md) の「設計のフォルダの型」。

1. **約束を書く（自分）**: `designs/<建物名>/base.py` の ★ を Step 2 の表と質問の答えで埋める
   （`STACK`・`ROOF`・`PAL`・`BAND`・`SHAPE`・`ENTRANCE`・`cameras(c)`・`sections(c)`）。
   入口一式（衝立・通り道・植え込み・通路・扉・帯の延長・自動扉）と室内は、組み立て役が `ENTRANCE` から置く（自分で組まない）
2. **受け持ちの表を書く（自分）**: `designs/<建物名>/plan.md` の ★ を埋める（面の長さ・質問の答えの1行・部位表・行ごとの渡す数）。
   **1行 = 1 Agent = 1ファイル**。看板は1枚ずつ、屋上・帯・面ごとの作りも別々の行にする。写真に無い部位の行は消す
3. **Agent を並列に起動する**: Agent ツール（`model: "sonnet"`）を、表の行の数だけ**1つのメッセージでまとめて**呼ぶ。
   依頼文は plan.md の「各 Agent に渡す依頼文」を行ごとに埋めた物。Agent は自分のファイルだけを書き、
   `REMODEL_ONLY=<名前>` で自分のパーツだけを描いて確かめる。
   Agent ツールが使えない時（自分がサブエージェントの時）は、ここで止めて plan.md ができたことを報告し、呼び出し元に起動してもらう
4. **組み立てて見る（自分）**: 全員の報告がそろったら Step 4 へ（`preview` で全部が組み立てられる）。
   報告の「置いた物の数」を部位表と照らし、違うパーツだけ、その Agent に直してもらう

- **高さは `c.G`（地面）・`c.F`（床）・`c.top`（帯の段）から書く。接する部位は相手の基準で**（衝立の上 ＝ `top - 1`。地面から数えた数を並べない）
- **部品は [parts.md](parts.md) の早見表で選ぶ**（parts.py のコードを読まない）
- **位置は `parts.Facade(c, 面)` で「外から見て左の角から何マス」と書く**（質問の答えの言い方のまま。例 `west = parts.Facade(c, "w")`、
  扉 `[west.at(11), west.at(12)]`、看板 `west.at(10, out=2)`）。**座標（x・z の数）を直書きしない**（ワールドを作り直すと壊れる）
- 看板は1枚ずつのパーツの `signs(geo, c)` と `images()`（`sign_art` の型）、カメラは `base.py` の `cameras(c)`（`parts.camera`）で、どちらも座標を書かない

### Step 4: プレビューで写真と比べる
```
cd tools/remodel
python run.py <建物名> preview v1     # 置かずに描く → out/v1_street.png, out/v1_top.png（最後に自動チェックも出る）
python run.py <建物名> section        # base.py の sections(c) の断面を AA で出す（入口・衝立・通路・仕掛け）
python run.py <建物名> check          # すき間・沈んだ看板・見える回路を探す
```
**断面の AA は、お手本と1段ずつ見比べる**（帯の下にすき間が無いか、看板が足元に沈んでいないか、床がハーフずつ上がるか）。
`base.py` に `sections(c)`（名前, 軸, 値）を書いておく。入口の中心・衝立の端・通路・自動扉の仕掛けは必ず入れる。
**`check` の警告は全部なくしてから施工する**（`build` は警告があると止まる。意図どおりの時だけ、ユーザーに確かめてから `build force`）。
写真と描画を上下に並べた1枚を作り、法則の順（大きさ → 数 → 差し色 → 奥行き）に違いを探す。
**1回に直すのは1か所**。直したら必ずもう一度描く。**プレビューと修正は最大3回まで**で、3回で施工に進む
（それ以上は法則の側を疑う。残りはゲーム内で見てもらって直す）。
カメラが構造物の中に入ったら、真上の図で空いている所に置き直す。
**入口の正面からの絵も必ず描く**（`cameras(c)` に `front`: 入口の正面 10 マスほど離れて目の高さ 1.6、`vfov` は書かない＝`view.json` の視野角）。
人の目の高さの絵で、看板・衝立・帯が**人の体と比べて**お手本と同じ高さに見えるかを、自分で確かめてから施工する。
写真の斜めの視点だけでは入口の違いに気づかない。比べる見本がゲーム内のスクショなら、同じ視野角・同じくらいの距離で描く
（近すぎ・視野角が狭すぎると建物の一部しか写らず比べられない）。

### Step 5: 施工
**施工の前に、プレビューの絵をユーザーに見せて確認をもらう**（写真と同じ視点・入口の正面・上から）。
「良い」と言われてから `build` する。直してと言われたら、直してもう一度見せる（ユーザー指定 2026-10-04）。
```
python run.py <建物名> build "メモ"   # チェック → 解体 → 控え → 施工 → 仕掛け → 飾り（付いたか確かめる）→ 看板の地図アート
python run.py <建物名> reset          # 更地に戻す（額縁も消す）
```

施工の最初に**解体**が自動で走る（`run.py` の `demolish`）。元の建物の土台からつながっているブロック
（敷地の外にはみ出した屋根・柵など）を、土台から6マス以内・ほかの建物に入らない範囲で全部たどって消す。
消した場所も控えに入るので `reset` で戻せる。

### Step 6: ゲーム内で確認
実際に**入口から歩いて入れるか**も確かめてもらう。
自前の描画は旗・額縁・光を描けない。テレポート先の座標をユーザーに伝え、見てもらう。
浮いているブロック、看板の表示、窓が隠れていないかを確認してもらい、1か所ずつ直す。
**ユーザーがゲーム内で手直ししたら、その状態を正解にする**: `run.py <建物> capture <保存先>` で敷地のブロックと看板の額縁を保存し、
`run.py <建物> diff <保存先>` の違いが無くなるまで設計のコードを直す（お手本はコード。JSON は確かめるための控え）。
直した理由（手直しから読めた決まり）は、辞書と 1.5 に書き足す。
