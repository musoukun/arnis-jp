# 質問フォーム（ウィジェット）の作り方

[SKILL.md](../SKILL.md) の「0. 聞いてから作る」で、ユーザーに位置・幅・作りの案・ブロックを聞く時に使う。
フォームは一から書かず、型（スキルの `scripts/ask_form.py`）に質問の JSON を渡して作る。フォームと質問は作業フォルダ（`image2mc/`）に置く。

## 決まり
- **出すのは会話している本体のモデル**。サブエージェントに任せない
  （サブエージェントが出したウィジェットはユーザーのチャットに出ない。2026-10-05 のガストでは、
  1回目は出力が止められ、2回目は「呼べた」の報告だけで実際には出ておらず、2回で約27万トークン・2分半かかった。
  本体が直接呼んだら1回で出た）
- **出たかを確かめてから**「出しました」と言う。失敗したら返ってきたエラーをそのまま伝える。
  理由を推測で決めつけない（「重いせい」など）。文字の選択式（`AskUserQuestion`）に勝手に切り替えない
- **フォームは小さく**: マス・繰り返しの部品は JS で描く作り（型がそうなっている）。HTML に1マスずつ書き出さない
  （前の型は図のマスを1つずつ `<div>` にしていて 126KB・`<div>` 1600 個近くになり、読む上限にも当たった）

## 手順
0. **面の長さを測る**（質問を作る前に）: スキルの `assets/parts_template/` を作業フォルダの `image2mc/designs/<建物名>/` にコピーし、
   `base.py` の `WAY`・`EXCLUDE`・`SHAPE`（ずらす・広げるの推測）を入れて `python <スキル>/scripts/run.py <建物名> faces`。
   スライダーの `length` は面全体のマス数、位置は出てきた k（左の角が 0）で書く。
   建物の大きさを聞く質問の答えで SHAPE が変わったら、測り直す
1. **質問の一覧を JSON に書く**（作業フォルダの `image2mc/specs/<名前>.json`。形と例は `ask_form.py` の先頭）。種類は3つ:
   - 位置・幅 = `slider`: ブロックで描いた正面の壁の上で、扉や看板がスライダーで動く
   - 作りの案 = `choice`: 上から見た図をブロックで描いて並べる。何を比べているのかが図で分かるように
   - ブロック = `block`: 色ではなく実物のテクスチャの見本
2. **型で HTML にする**: `python <スキル>/scripts/ask_form.py image2mc/specs/<名前>.json` → `image2mc/out/ask_<名前>.html`。
   型が大きさ（KB）と `<div>` の数を表示し、目安（50KB・`<div>` 300 個）を超えたら止まる。
   止まったら質問を分けるか図を小さくする
3. **本体が出す**: ToolSearch で `select:mcp__visualize__read_me,mcp__visualize__show_widget` を読み込み、
   `read_me`（modules `["interactive"]`）を呼んでから、`image2mc/out/ask_<名前>.html` を Read で読み、
   `show_widget` の widget_code にその中身を一字一句そのまま渡す
4. **出たかを確かめる**: `show_widget` が成功を返したかを見る（上の決まり）
5. **答えを受け取る**: 「〇〇 の答え: 扉の位置=北の角から11マス / …」の1行でユーザーから届く。フォームを撮って確かめる必要はない

## 質問と図の描き方
- **別々の部位は、別々の質問にする**（左右の通路なら「左の通路の位置」「右の通路の位置」の2問。1つの操作で2つを動かさない）
- **ゲームの座標（x・z の数字）を質問に出さない**。相手に分かるのは「北の角から何マス」「正面の真ん中から南へ何マス」「左右」「手前・奥」
- 絵には目の位置と向き、北と南（左右）、正面の真ん中の目印、人の目印（高さ2マス）を入れる
- 上から見た図と正面から見た図を1つの絵に混ぜない
- 大きさ（幅・通路・入口）は、`run.py` が表示するワールド倍率のマス数で作る（[SKILL.md](../SKILL.md) の法則1）
